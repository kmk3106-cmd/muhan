# 액면분할·병합 대응 검토서

> 상태: **검토 완료 · 미구현** (2026-09-18)
> 범위: 무한매수법 · 떨사오팔 · 종사종팔 (KIS) + VR 0기·5기 (NH)
> 방법: 운영 DB 4개 전 테이블·컬럼 전수 분류 + 체결 적재·싸이클 판정·감사·화면 코드 경로 추적

---

## 0. 결론

1. **현재 대응 코드 없음.** 분할·병합 감지, 소급수정, 주문 차단 전부 없다.
2. **감지만으로는 부족하다.**
   - 분할 전에 사서 분할 후에 파는 포지션은 기록이 두 단위로 섞여 **싸이클 판정·매도가·감사가 영구히 틀어진다** → 소급수정 필수
   - VR은 2주짜리 예약주문이 **이미 증권사에 걸려 있어** 분할 당일 개장과 동시에 옛 가격으로 체결된다 → 사후 감지로는 못 막는다. **공시 시점 사전 등록**이 1차 방어선이어야 한다
3. **치명 결함 4건** (§2). 이 중 C2는 병합 한 번이면 무한매수법 싸이클이 영원히 안 닫힌다.
4. **소급수정은 "분할일을 가로지르는 것만" 하면 된다** (§4). 이미 닫힌 싸이클은 전부 분할 전 단위로 일관돼 있어 손댈 필요가 없고, 원본을 보존해야 증권사 거래명세와 대조할 수 있다.
5. **병합이 분할보다 어렵다.** 트렌치 구조 자체가 성립하지 않는 경우가 생긴다 (현재 SPXL 트렌치 2주씩 → 1:10 병합 시 전 트렌치 소멸). 사용자 결정 필요 (§9).

## 1. 데이터 분류 — 무엇이 바뀌고 무엇이 안 바뀌나

분할 비율을 **r** (2:1 분할 r=2, 1:10 병합 r=0.1)이라 하면
**주당 가격 ÷ r · 주식 수 × r · 달러·비율·T값 불변.**

### 불변 🟢 (수정 불필요)

| 대상 | 이유 |
|---|---|
| 금액 컬럼 전부 — amount, cum_buy/sell_amount, total_buy/sell_amount, profit, seed, B, total_usd, amount_per_tranche, quarter_base_cash, initial_holdings_cost | 달러 |
| 비율 — R, x_pct, star_pct, profit_pct, buy_limit_pct | % |
| **T값** | `보유원가 ÷ B` — 원가(달러) 불변 |
| VR — V, 밴드, Pool, E, 적립/인출, weekly_history 전부 | 달러 |
| core — 자산추이, 현금흐름, 시드할당, 복리상태 | 달러 |

### 가변 (주당 단위)

| 전략 | 테이블.컬럼 | 쓰임 | 방치 시 |
|---|---|---|---|
| 무한매수법 | portfolio_states.avg_price, qty | 주문가·수량·쿼터 1/4 | 🟢 매 동기화 KIS 잔고로 덮어씀 |
| | trades.price, qty, order_price | **싸이클 종료 판정(수량합)**, 회차 표시, 감사 | 🔴 C2 |
| | orders.price, qty | 이력 표시 | 🟡 |
| 떨사오팔·종사종팔 | tranches.avg_price, buy_price, qty | **매도가, 전체평단, 매도수량** | 🔴 C3 · H1 |
| | trades.price, qty | 감사(수량합), 표시 | 🟠 H2 |

## 2. 발견된 결함

### C1 🔴🔴 VR 예약주문이 옛 가격으로 일괄 체결

- 사다리 가격 = `밴드 ÷ 모델잔여`. 모델잔여(0기 430, 5기 216)는 DB값이라 분할을 모른다.
- 더 큰 문제: **2주 기간잔량 예약이 이미 NH에 걸려 있다** (현재 0기 260주차 19건, 5기 51주차 22건).
- **2:1 분할** (TQQQ $72 → $36): 매수 지정가 $56.96~60.65가 시가보다 높아 **매수 8단 개장 즉시 전량 체결**. 매도 $82~93은 영영 안 닿음.
- **1:10 병합** (→ $720): 매도 지정가 $82~93이 시가보다 낮아 **매도 14단 개장 즉시 체결 시도**.
- NH가 권리 발생 시 예약주문을 자동 취소하는지 **미확인** (§8). 확인 전까지는 체결된다고 가정해야 한다.
- 우리가 분할을 알아챌 수 있는 건 NH 잔고가 바뀐 뒤 = 개장 직전~직후. **사후 감지로는 늦다.**

### C2 🔴 무한매수법 — 병합 시 싸이클이 영원히 안 닫힘

`strategies/infinite/worker.py:919-934` `_check_cycle_end`

```python
net_qty = Σ매수수량 − Σ매도수량      # 현재 싸이클 trades
if net_qty > 0:
    return False                    # 아직 청산 전으로 판정
```

- 싸이클 중 1:10 병합 → 병합 전 매수 370주 기록 → 병합 후 37주 전량 매도 → net_qty = 370 − 37 = **333 > 0**
- 잔고는 0인데 **싸이클 종료로 인정 안 함** → 이력 미기록, 회차·T 리셋 안 됨, 복리 증액 안 됨, 다음 싸이클 최초매수 꼬임
- 2:1 분할은 net_qty가 음수라 통과 → **병합에서만** 터진다

### C3 🔴 트렌치 매도가 오산정

`strategies/ddsop/trading_logic.py:120` — `sell_price = tranche.avg_price × (1 + x%)`

- **2:1 분할**: DB 평단 $299 그대로, 실제가 ~$140 → 매도가 영영 안 닿음 → 익절 불가, 손절일까지 방치
- **1:10 병합**: DB 평단 $299 그대로, 실제가 ~$2,800 → 매도조건 즉시 충족 → **DB 수량(2주)으로 매도 주문 → 실제 보유 0.2주** → 거부 또는 오매도

### C4 🔴 VR 체결 중복판정 키가 "행 전체 해시"

`strategies/vr/worker.py:25-60` `_parse_fill` — `dedup_key = sha256(행의 모든 필드)`

- NH가 분할 후 과거 거래내역 단가·수량을 소급 재진술하면 **같은 체결의 키가 바뀐다** → 새 체결로 오인 → **모델잔여·Pool 이중 반영**
- 분할과 무관하게도 NH가 표시용 필드 하나만 바꿔도 같은 사고가 난다 → **분할 대응과 별개로 먼저 고쳐야 한다**
- 참고 — KIS 3전략은 이 문제가 **없다**:
  - 무한매수법: **주문번호(odno)**로 중복판정 (`infinite/worker.py:1083-1108`)
  - 떨사오팔·종사종팔: **미체결 주문번호 매칭 후 filled 전환** (`ddsop/worker.py:427-470`)
  - → KIS가 과거 체결을 소급 조정하든 말든 중복 적재는 없다

### H1 🟠 종사종팔 전체평단

`strategies/jongsa/trading_logic.py:138-161` — 일괄매도 기준 가중평균 평단을 **DB 트렌치**로 계산 → C3과 같은 방식으로 틀어짐. 자전거래 가드(매수가 ≤ 최저매도가×0.995)도 같이 틀어짐.

### H2 🟠 싸이클 정합 감사 오탐

`core/t_audit.py:194, 324` — 싸이클별 `매수수량합 ≠ 매도수량합`이면 불일치. 분할이 낀 싸이클은 소급수정 전까지 **매일 09:00 오탐**.

### M1 🟡 VR 단위(unit) 재정의

- 모델잔여만 ×r 하고 단위(0기 4, 5기 2)를 그대로 두면 한 칸 금액이 1/r로 바뀐다. 유지하려면 단위도 ×r.
- **병합(r=0.1)이면 단위 2 → 0.2주 — 정수 불가.** 라오어가 병합 후 모델을 어떻게 재정의하는지 따라야 한다 → **라오어 공개표 기준 재설정**.

### M2 🟡 경계일 정의 — 테이블마다 날짜 의미가 다르다

소급수정 대상 = **ex-date(미국 거래일) 이전 체결.** 그런데:

| 컬럼 | 의미 |
|---|---|
| infinite.trades.trade_date, ddsop/jongsa.trades.trade_date | KIS `ord_dt` (주문일) |
| infinite.orders.created_at 등 | **UTC** (`datetime.utcnow`) — 23:00 KST 워커 주문이 14:00으로 저장됨 |
| vr.reserved_orders.start_dt/end_dt | 미국 거래일 |

테이블별로 "이 날짜가 미국 몇 일 세션인가"를 확정해 경계를 적용해야 한다.

### L1 ⚪ 화면·기록

- 체결내역·싸이클 상세의 과거 단가가 분할 전 값 → 평단이 계단식으로 끊겨 보임 → 분할 표시선으로 처리
- 매매일지(블로그) 기발행분은 수정 불가 → 분할 이후 일지에 "○/○ 분할 1:r, 이전 단가 ÷r" 한 줄 명시

### 안전 확인 🟢

- 무한매수법 주문가·수량·T값·쿼터 1/4 수량 — 매번 KIS 잔고(평단·수량)에서 새로 계산
- KIS 3전략 체결 적재 중복판정 — 주문번호 기준 (C4 참고)
- 달러 기반 전부 — 시드, 복리, 자산추이, 현금흐름, 싸이클 손익

## 4. 소급수정 범위 — "분할일을 가로지르는 것만"

**이미 닫힌 싸이클은 수정할 필요가 없다.** 매수·매도가 전부 분할 전 단위로 기록돼 그 자체로 정합하다 (수량합 일치, 달러 손익 정확). 깨지는 건 **분할 전에 사서 분할 후에 파는 열린 포지션**뿐이다.

| 구분 | 대상 | 처리 |
|---|---|---|
| **필수** (매매 영향) | 무한매수법 — 진행 중 싸이클의 ex-date 이전 trades | price ÷r, order_price ÷r, qty ×r |
| | 떨사오팔·종사종팔 — 보유 트렌치 | avg_price ÷r, buy_price ÷r, qty ×r |
| | 〃 — 보유 트렌치의 ex-date 이전 매수 trades | price ÷r, qty ×r |
| | VR — gisu | model_qty ×r, unit 라오어 기준 재설정 |
| | VR — 걸린 예약 | **취소 → 재산출 → 재제출** |
| | VR — 현 주기 fills | price ÷r, qty_acct ×r |
| **보존** (수정 안 함) | 닫힌 싸이클 trades·orders·trade_orders | 증권사 거래명세와 대조 가능하도록 원본 유지. 화면에 분할 표시선만 |
| | 달러·비율·T값, _t_audit.jsonl, 블로그 기발행분 | |
| | 무한매수법 portfolio_states | 다음 동기화가 KIS 잔고로 덮어씀 → 적용 직후 강제 동기화로 확인 |

## 5. 수정 방식

| | A안 — 값 직접 수정 | B안 — 조정계수 컬럼 |
|---|---|---|
| 방식 | 해당 행의 price·qty를 r로 고쳐 씀 | 원본 유지, 행마다 `adj_factor`, 합산 시 `qty × adj_factor` |
| 매매 로직 | **무변경** | 수량 합산 경로 전부 수정 (싸이클 종료·감사·가중평단·표시) |
| 누락 위험 | 없음 | 하나라도 빠지면 조용히 틀림 |
| 원본 | 백업으로 보존 | 테이블에 보존 |

**권고: A안.** §4처럼 필수 범위가 좁아서(열린 싸이클·보유분) B안으로 전 경로를 고칠 이유가 없고, 운영 시스템 최소변경 원칙에도 맞다.

- **병합 소수 문제**는 열린 싸이클 trades에서만 생긴다 (병합 전 7주 → 0.7주). 해당 행만 소수 보관 + 싸이클 종료 판정에 허용오차(`net_qty > 0.5`) — C2 수정 겸용.
- 전 과정 **이벤트 원장**(멱등) + 적용 전 **4개 DB·core 파일 스냅샷 백업** → 원클릭 롤백.

## 6. 설계 원칙

1. **사전 등록이 1차 방어, 감지는 2차 방어**
   - 레버리지 ETF 분할·병합은 보통 1~2주 전 공시된다 → 대시보드에 `(티커, ex-date, 비율)` 등록
   - 등록 시: ex-date 전 마지막 영업일에 해당 티커 **VR 예약 전량 취소**, ex-date 당일 **전 전략 신규주문 차단**
   - 놓쳤을 때 대비 **감지**: 매 동기화마다 DB 기대수량 vs 증권사 실제수량이 정수비로 어긋나고 가격도 같은 비율로 움직이면 → 해당 티커 전 전략 자동 정지 + 빨간 배너
2. **자동 적용 금지** — 감지돼도 소급수정은 사용자 확인 후. HTS 직접매매로도 수량이 어긋나기 때문 (예: 과거 UPRO 유령 9주). 오판 시 장부를 망가뜨린다
3. **멱등성** — 이벤트 상태 `registered → halted → applied → resumed`, 같은 이벤트 이중 적용 차단
4. **원자성** — 한 티커의 모든 전략·DB를 한 번에. 하나라도 실패하면 전부 롤백
5. **티커 단위** — 증권사·전략을 가로질러 일괄 (TQQQ = KIS 무한매수법 + NH VR 2개)
6. **재개는 검증 후** — 적용 → 강제 동기화 → DB 수량 = 증권사 수량 확인 → 미리보기 가격이 현재가 근처인지 확인 → 사용자가 킬스위치 해제

## 7. 처리 절차

| 시점 | 할 일 |
|---|---|
| 공시 확인 | 대시보드에 분할 등록 (티커 · ex-date · 비율) |
| ex-date −1 영업일 | 해당 티커 VR 예약 전량 취소 (NH `reservedCancel`), 전 전략 신규주문 차단 |
| ex-date 당일 | 주문 없음. 동기화만 → 증권사 잔고 반영 확인 |
| 반영 확인 후 | 실제 수량·평단으로 비율 재확인 → 백업 → 소급수정 → 강제 동기화 → 정합 확인 |
| 사용자 확인 | 미리보기 확인 → 킬스위치 해제. VR은 라오어 공개표로 모델 재설정 후 재제출 |

---

## 8. 미확인 사항 (실측 또는 증권사 문의 필요)

1. **NH·KIS가 분할 시 걸린 주문을 자동 취소하는가** — 특히 NH 기간예약주문. 취소해준다면 C1 위험이 크게 준다
2. **증권사 잔고 반영 시점** — ex-date KST 아침? 미국 개장 시? 23:00 주문 워커보다 먼저인가
3. **과거 체결내역 소급 재진술 여부** — KIS `inquire-ccnl`, NH `dailyTransaction` (KIS 3전략은 무관, VR은 C4 수정 후 무관)
4. **전일종가가 수정주가인가** — ex-date에 떨사오팔 매수가(`전일종가×(1−x%)`)와 무한매수법 매수캡이 수정 전 종가를 쓰는지
5. **권리 입고/출고 행 형태** — VR `_parse_fill`이 분할 당일 거래내역을 매수/매도로 오인하지 않는지
6. **KIS 해외 권리(분할) 조회 API 존재 여부** — 있으면 사전 등록 자동화 가능

## 9. 사용자 결정 필요

1. **병합 시 트렌치 단주 처리** — 예: UPRO 7트렌치 × 9주 → 1:10 병합 후 6주
   - (가) 트렌치 수를 줄여 재구성 (6트렌치 × 1주 등)
   - (나) 해당 싸이클 강제 종료 (현재가 정산 기록) 후 새 싸이클
   - (다) 단주는 마지막 트렌치부터 깎고 현금정산분은 실현손익 처리
2. **VR 병합 시 모델 재설정** — 라오어 공개표를 기다려 수동 재설정 / 임시로 단위 반올림 운용
3. **소급수정 방식** — A안 (권고) / B안
4. **C4를 분할 대응보다 먼저 고칠지** — 분할과 무관한 잠재 버그
