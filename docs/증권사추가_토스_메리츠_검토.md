# 증권사 추가 검토 — 토스증권 · 메리츠증권 (2026-09-24)

사용자 요청: "토스증권, 메리츠증권 추가하도록" → **조사만 수행, 코드 변경 없음(보류)**.
현재 운용: KIS 공용계좌 1개(무한매수법·떨사오팔·종사종팔) + NH PLUG 2계좌(VR 0기·5기).

## 1. 결론

| 항목 | 토스증권 | 메리츠증권 |
|---|---|---|
| 오픈 API | 정식 출시 (REST, OAuth 2.0) | 있음 (REST + WebSocket) |
| 미국주식 시세 | O | O (해외 현재가) |
| **미국주식 주문** | **O** | **공식 예제는 국내주식 주문만** — 해외주문 미확인 |
| LOC (종가 지정가) | **O** — `orderType=LIMIT` + `timeInForce=CLS` (미국주식 한정) | 미확인 |
| MOC (종가 시장가) | **X** — CLS 는 LIMIT 에만 결합 | 미확인 |
| 기간 예약주문(2주 잔량) | **X** — 조건주문(SINGLE/OCO/OTO)만 | 미확인 |
| 호출 제한 | 주문 10회/초, 시세 15회/초, 인증 5회/초, 조건주문 5회/초 | 미확인 |

→ **토스**: 매매 연동 가능성 있음. 단 MOC·기간예약이 없어 전략 규칙 변경이 필요하다.
→ **메리츠**: 현재 문서·예제 기준으로 미국 ETF 자동매매에는 쓸 수 없다. 국내주식 전략을 새로 만들 때 후보.

## 2. 우리 전략이 요구하는 주문유형 vs 토스

| 전략 | 필요한 주문 | 토스 | 비고 |
|---|---|---|---|
| 무한매수법 | LOC 매수(평단·☆%), LOC 매도(+R%), **MOC 매도(쿼터 1/4 손절)**, LIMIT 매도 3/4 | LOC·LIMIT O / MOC X | 쿼터 손절을 LOC 로 대체할지 결정 필요 |
| 떨사오팔 | LOC 매수(−x%), LOC 매도(평단+x%), **MOC 손절(40거래일)** | 동일 | 〃 |
| 종사종팔 | LOC 종가매수(한도 전일종가+15%), LOC 일괄매도, **MOC 손절** | 동일 | 〃 |
| VR | **2주 기간잔량 지정가 예약** (NH 고유) | X | 서버가 매일 그날 사다리를 DAY 주문으로 제출하는 방식으로 대체 |

### MOC → LOC 대체 시 주의
- MOC 는 종가에 **무조건** 체결된다. LOC 매도는 **종가 ≥ 지정가** 일 때만 체결된다.
- 지정가를 아주 낮게 두면 사실상 MOC 와 같아지지만, 미국 종가단일가(closing auction)에는
  **LOC 가격 제한(price collar)** 이 있어 기준가에서 크게 벗어난 지정가는 거부·조정될 수 있다.
  → 실제 허용 범위를 토스 문서/고객센터로 확인하기 전에는 "손절이 반드시 체결된다"고 가정하지 말 것.
- 손절 미체결은 전략의 위험 관리 전제를 깨뜨린다. 규칙 변경은 사용자 승인 필요.

## 3. 신청 절차 (사용자 본인만 가능)

### 토스증권 (공식 안내·FAQ 기준)
1. 토스증권 계좌 개설 — **계좌 보유자 본인만 발급 가능, 만 19세 이상**
2. PC 웹 WTS 로그인 → **설정 > Open API** → `client_id` / `client_secret` 발급
   (화면의 복사 버튼으로 복사. 앞뒤 공백·줄바꿈이 섞이면 `invalid_client` 발생)
3. 같은 화면의 **허용 IP** 에 호출 IP 등록 — 우리 운영 서버 `49.50.135.220` (고정 IP)
   미등록 IP 는 키가 맞아도 403. 호출 때마다 IP 가 바뀌는 환경은 사용 불가.
4. 토큰: `POST https://openapi.tossinvest.com/oauth2/token` (OAuth2 Client Credentials).
   **클라이언트당 유효 토큰 1개** — 새로 발급하면 이전 토큰은 즉시 무효(`401 token-revoked`).
   전략별로 따로 발급하면 서로를 무효화하므로 **한 토큰을 공유**해야 한다(현재 단일 프로세스라 적합).
5. 계좌·자산·주문 API 는 `Authorization: Bearer` 에 더해 **`X-Tossinvest-Account` 헤더** 필요.
6. 키는 채팅에 붙여넣지 말고 서버의 자격 파일(`/root/trading_suite_state/…`)에 직접 넣는다.
   NH 와 같은 방식(배포와 무관하게 보존되는 디렉터리).

#### 토스 이용 조건·제약 (공식)
- API 로 **입출금·환전 불가**. 본인 매매 목적만 허용, 외부 배포·상업적 이용 금지.
- **미국 레버리지·인버스 ETF 는 사전 요건(투자성향 등록·위험고지·약관 동의) 미완료 시
  `prerequisite-required` 로 주문 거부** → 토스증권 앱에서 해당 종목 구매 화면에 들어가
  등록 절차를 끝내야 한다. 우리 종목(TQQQ·SOXL·TECL·SPXL·UPRO)이 전부 3배 레버리지라 필수.
- 짧은 시간에 소액 주문을 대량 반복하면 어뷰징으로 **일정 기간 매매 제한**될 수 있다.
- 주문·체결 조회는 **주문 1건 = 1행**(평균 체결가·총 체결수량, 시각은 마지막 체결 기준).
  건별 체결 조회 REST 는 없고, 건별이 필요하면 웹소켓 `personal:order` 채널을 쓴다.
- 미국 시세는 NBBO 가 아니라 일부 거래소 기준. 일봉 종가는 정규장 공식 종가.
- 수수료: 미국주식 0.1%(주문건별 총 체결금액 10달러 이하 무료), 국내 KRX 0.015%·NXT 0.014%.

### 메리츠증권
- 개발자 포털 `openapi.imeritz.com` 에서 신청. 해외주식 주문 지원 여부를 **고객센터로 먼저 확인**할 것.

## 4. 연동 범위별 작업량

### (A) 조회 전용 — 자산 합산만
- 계좌·보유·예수금만 읽어 대시보드 총자산/포트폴리오에 합산.
- 매매 코드 무변경 → 사고 위험 없음. 작업 작음.
- 필요한 것: 브로커별 조회 어댑터 1개, 계좌 등록 화면, 대시보드 합산(현재 KIS+NH 합산 로직 확장).

### (B) 매매까지 — 토스 계좌에서 전략 운용
현재 구조가 "KIS 1계좌 + 티커 전 전략 유일" 전제라 다음이 모두 필요하다.
1. 브로커 추상화: 인증·현재가·잔고·주문·정정/취소·체결조회 인터페이스 (KIS/NH/토스 구현체)
2. 전략–계좌 귀속: 전략마다 어느 증권사·어느 계좌인지 설정, 티커 유일성 규칙을 계좌 단위로 재정의
3. 주문유형 매핑 계층 (LOC/MOC/LIMIT → 브로커별 코드) + MOC 미지원 시 정책
4. 체결 동기화·싸이클 정산을 브로커별 응답 형식에 맞게 (KIS `ccnl`, NH `dailyTransaction`, 토스 orders/holdings)
5. 스케줄 레인 분리(호출 제한 회피), 계좌별 예수금 가드레일, Kill Switch
6. 계좌·키 등록 화면 (현재는 무한매수법 옛 대시보드에만 KIS 키 폼이 있고, 세 전략 DB 에 각각 저장됨)
7. 검증: 실계좌 소액 주문으로 LOC 체결·부분체결·취소·체결조회 왕복 확인

## 5. 확인이 더 필요한 것

- 토스: LOC 지정가 허용 범위(가격 제한), 부분체결 표기, 주문 상태 코드, 토큰 수명·갱신, 동시 세션,
  모의투자(샌드박스) 제공 여부, 해외주식 거래시간·서머타임 처리, 수수료 조회(`/commission`) 활용
- 메리츠: 해외주식 주문 지원 계획과 시점
- 공통: 계좌를 늘리면 한 종목을 두 계좌에서 잡게 되는 경우의 처리(현재는 티커 중복 금지로 막고 있음)
