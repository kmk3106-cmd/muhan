## 1. v4 변경분 찾기

비교 기준은 `origin/master` = **`a8526be`** (2026-09-24, 이 시점엔 아직 v3).

```bash
# 작업용 클린 체크아웃
git fetch origin
git worktree add /tmp/base_v3 a8526be      # 또는 별도 클론

# 서버 ↔ v3 전체 비교 (코드만)
diff -ruN --exclude='*.db' --exclude='__pycache__' --exclude='*.log' \
     --exclude='.kill_switch' --exclude='_*.json' --exclude='_*.jsonl' \
     /tmp/base_v3 /root/trading_suite | tee /tmp/v4_diff.txt

# 핵심 파일만 빠르게
diff -u /tmp/base_v3/strategies/jongsa/trading_logic.py \
        /root/trading_suite/strategies/jongsa/trading_logic.py
diff -u /tmp/base_v3/core/compound_mode.py \
        /root/trading_suite/core/compound_mode.py
```

**로컬 작업폴더도 확인할 것.** 그 세션이 PC에서 고쳐 올렸다면 로컬에 원본이 남아 있을 수 있다.
서버본과 로컬본이 다르면 **서버본이 실제 돌고 있는 것**이므로 서버본을 기준으로 한다.

`/root/trading_suite.bak` 에 직전 버전이 한 겹 남아 있다. 그 뒤 배포가 또 있었다면 이미 덮였을 수 있으니
`ls -la /root/trading_suite.bak/strategies/jongsa/trading_logic.py` 로 날짜부터 확인할 것.

### v4 가 맞는지 판별하는 기준

`docs/종사종팔_사양.md` **§9.2** 에 원문이 있다. v3 대비 **딱 두 가지**만 다르다:

1. **매수(b)**: 매일 투자금 1/10 종가 매수 — 단, **매도가 발생한 날은 익절·손절 모두 매수 금지**
2. **복리(e)**: 재투자 비율 **35% → 70%**

코드에서 확인할 것:
- `generate_orders` 에서 손절 대상(`loss_cut_ids`)이 있는 날 **매수 주문을 만들지 않는지**
  (v3 는 `loss_cut_ids` 를 계산해 놓고도 아래에서 매수를 무조건 붙인다)
- 복리 비율 `0.7` 이 어디에 있는지. 원문은 "**지난 20~10일**(= 2사이클 전, 1사이클 = 10거래일)
  수익의 70% 를 향후 10일 **일별 목표투자금**에 증액, 손실이면 감액 없이 유지" 다.
  현 레포의 `core/compound_mode.py` 는 "싸이클 종료 시 누적 실현손익 **전액**을 시드에 증액"
  이라 **축이 다른 모델**이다. 서버 v4 가 어느 쪽인지 반드시 확인할 것.

## 2. ⚠️ 먼저 v4 를 있는 그대로 커밋·푸시 (최우선)

정리·병합은 그 다음이다. **이 단계 전에 배포 금지.**

```bash
git switch -c jongsa-v4-recover a8526be     # v4 가 기반한 커밋에서 분기
# 서버본 코드 파일을 작업트리로 복사 (DB·상태파일·로그·토큰은 제외)
#   예: cp /root/trading_suite/strategies/jongsa/trading_logic.py strategies/jongsa/
#       cp /root/trading_suite/core/compound_mode.py core/      ← 바뀌었다면
git add -A
git status            # 의도한 파일만 올라가는지 눈으로 확인
git commit -m "recover(jongsa): 서버에서 운영 중이던 종사종팔 v4 코드 — git 밖에 있던 것을 그대로 보존"
git push -u origin jongsa-v4-recover
```

**절대 하지 말 것**: `git push --force`, 기존 브랜치 히스토리 재작성, 비밀정보 커밋
(`kis_devlp.yaml`, `nh_plug.env`, 토큰 파일 — `.gitignore` 확인).

푸시가 끝나면 v4 는 더 이상 배포로 사라지지 않는다. 여기까지가 이 작업의 **절반 이상**이다.

**`strategies/jongsa/worker.py`** — 내가 추가·수정한 것:

  아무것도 취소하지 않고 반환), `_get_kis_pending_order_keys()` (조회 실패 시 KIS 대조 생략)

기존 `inquire_nccs()` 는 결과만 돌려주는 래퍼로 남겨 기존 호출부 호환.

> v4 는 주로 `trading_logic.py` 를 고쳤을 테니 안 겹칠 가능성이 높다.
> **겹치면 v4 의 매매 규칙(매도일 매수 금지·복리 70%)을 우선하되, 위 가드·fail-safe 는 반드시 살려서 합칠 것.**
> 둘은 목적이 다르다 — v4 는 "무엇을 주문할까", 가드는 "그 주문이 거부·중복되지 않게".

떨사오팔(`ddsop`)도 같은 코드라 양쪽이 **AST 동일**하게 유지돼 있다. 병합 후에도 동일한지 확인할 것:

```bash
python3 - <<'EOF'
import ast, hashlib
names = ("_get_kis_pending_odnos","_sync_pending_with_kis","_get_kis_pending_order_keys",
         "_get_sellable_qty","_fit_sells_to_capacity")
h = {}
for s in ("ddsop","jongsa"):
    t = ast.parse(open(f"strategies/{s}/worker.py",encoding="utf-8").read())
    h[s] = {n.name: hashlib.md5(ast.dump(ast.Module([n],[])).encode()).hexdigest()[:10]
            for n in ast.walk(t) if isinstance(n,ast.FunctionDef) and n.name in names}
for n in names:
    print(f"{n:32s} {'동일' if h['ddsop'].get(n)==h['jongsa'].get(n) and h['ddsop'].get(n) else '다름/없음'}")
EOF
```

## 5. 재발 방지 — `apply_deploy.sh` 에 가드 추가

이번 사고의 근본 원인은 "코드가 git 밖에만 있었다" 이고, 배포 스크립트가 그걸 말없이 덮는다.
폴더 교체(`mv "$NEW" "$APP"`) **직전에** 다음을 넣을 것:

1. 현재 운영 중인 `$APP` 와 새 패키지 `$NEW` 의 **코드 파일**을 비교
   (DB·`core/_*.json|jsonl`·`.kill_switch`·로그·토큰·`__pycache__` 제외)
2. `$APP` 에만 있거나 내용이 다른 파일이 **git 에 없는 변경**이면
   → **배포를 중단하고** 목록을 출력. `--force` 같은 명시적 플래그를 줬을 때만 진행
3. 중단 시 `$APP` 는 그대로 두고 프로세스도 재기동하지 말 것 (현 운영 상태 유지)

출력 예시:
```
[중단] 서버에만 있고 git 에 없는 변경 3건:
  strategies/jongsa/trading_logic.py
  core/compound_mode.py
먼저 커밋·푸시한 뒤 다시 배포하거나, 의도한 폐기면 --force 로 실행하세요.
```

## 참고 — 알려진 미해결 항목

- **종사종팔 장부 어긋남**: 취소로 오판됐다 나중에 체결된 주문은 `pending/submitted` 만 보는
  체결 매칭에서 빠져 트렌치에 반영되지 않는다. 매도 부분체결 시 트렌치를 `IDLE/qty=0` 으로
  밀어버리는 문제도 있다. 트렌치 상태머신을 건드려야 해서 보류 중.
- **무한매수법 T 계산**: 문서(`docs/T계산_로직_및_이슈분석.md`)는 `(cum_buy-cum_sell)/B` 인데
  실제 코드는 `calc_T_from_avg` (= 평단×수량/B) 만 쓴다. `calc_T` 는 죽은 코드.
- **쿼터 진입 조건**이 `39.1 <= T <= 40` 구간이라 T 가 40 을 넘겨 찍히면 진입하지 못한다.
- **VR 휴장일 표**가 하드코딩(2026·2027)이라 매년 초 갱신 필요. 안 하면 NH 23073 전량 거부.
- **자산추이 10일 최근성 제한**: 전량청산 후 10일 넘게 워커가 안 돌면 그 싸이클이 영구 누락.
